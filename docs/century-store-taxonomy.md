# 백년가게 CSV 매칭과 공통 분류

`src/lib/taxonomy.ts`가 PM v2 기준의 유일한 원본이다. `content_type_id` 8대 유형의
L1을 사용하되 음식점(39)의 베이커리/빵·떡/전통명과·카페/음료 L2에 한해
L1을 `카페/디저트`로 분기한다. 축제 L1 명칭은 `축제/행사`다. L2는 해당 유형의
허용 목록에서 하나 또는 null이며, PM 기준에 없는 쇼핑 L2는 임의 생성하지 않는다.
`filter_tags`는 근거 있는 업종·메뉴를 최대 12개 선택한다. `cat1~cat3`는 입력과
판단에 사용하지 않는다. 편의시설을 상호에서 추정하지 않는다.

```sh
npm run taxonomy:sync    # TypeScript 원본 → Python용 scripts/place_taxonomy.json
npm run taxonomy:check   # 생성물과 원본의 일치 검사
```

Python CSV/Gemini는 생성된 JSON을 동일하게 읽고, 정규식도 TS 원본에서 직렬화한
규칙을 사용한다. Node 회귀 테스트가 생성물의 불일치를 감지한다. JSON을 수동으로
편집하지 않는다. TypeScript의 `CATEGORY_L1_MAP`, `CATEGORY_L2_MASTER`,
`FOOD_L2_RULES`, `TAG_NORMALIZATION_MAP`, `resolveFoodCategory`,
`extractFilterTags`를 다른 제품에서도 직접 import할 수 있다.

주요사업이 상호명보다 우선하며 각 입력 안에서는 PM 규칙 순서대로 대표 L2를
선택한다. `떡볶이`·`떡갈비`·`떡국`을 디저트로 오분류하지 않고, 돈가스→돈까스,
까페→카페 등의 정규화·중복 제거·불용어 제거를 수행한다. 괄호와 복합 구분자를
처리하며, 의미 있는 한 글자 메뉴 태그(떡·회·차)는 허용한다. 백년가게 태그는
AI/주요사업 텍스트에서 생성하지 않고 검증된 CSV 매칭 경로에서만 부여한다.

기존 v1로 반영된 176건은 과거 실행 기록이다. 이번 마스터 변경만으로 DB를
일괄 재분류하지 않는다. CSV 스크립트 재실행 시 v1 출처의 값도 v2로 갱신할 수
있으며, 수동 출처는 계속 보존한다. SQL 함수도 v2의 카페 분기·축제 명칭에
맞춰 수정했으므로 AI worker 배포 전에 SQL을 함께 적용해야 한다.

## CSV 1차 대조

```sh
python scripts/import_century_stores.py
# 검토 후 확실한 후보에만 반영
python scripts/import_century_stores.py --apply
```

`npm run import:century`도 같은 읽기 전용 대조를 실행한다. Windows에서 기본
`python` 별칭이 실행되지 않으면 설치된 Python 실행 파일로 위 명령을 실행한다.
CSV는 UTF-8 BOM 또는 CP949를 자동 판별하고 정규 CSV 파서로 쉼표·인용문·개행을
처리한다. 실제 원본 1,262행을 읽으며 원본 CSV는 저장소에 추가하지 않는다.

DB는 활성 장소만 500행씩 PK 키셋으로 읽는다. 상호 정규화는 법인 표기와
구두점·공백에 한정하고 지점명을 버리지 않는다. 지역명 표기 차이를 정규화하며,
주소의 번지 하이픈은 보존한다. 동일 상호 + 전화 + 시군구 또는 동일 상호 +
정확한 주소를 자동 매칭한다. 전화·지역이 일치하는 긴 상호의 유사도 0.92 이상도
후보가 되지만, 차선 후보와 점수가 15 이상 차이 나야 한다. 상호만 같은 경우,
다른 지역, 동률 후보, 하나의 DB 장소에 여러 CSV 행이 매칭되면 검토 대상으로 남긴다.
DB에 없는 업소를 새로 생성하거나 약한 매칭으로 자동 반영하지 않는다.

결과는 `artifacts/century-stores/matching.json`에 자동 매칭/검토/미매칭과 상위
후보·매칭 근거를 저장한다. 적용 전에도 보고서를 생성한다. 적용 시 상호·주소·전화·
수정일·기존 분류·태그·CSV 정보의 관찰값을 모두 비교하는 조건부 PATCH로 한 행을
원자적으로 갱신한다. 충돌/오류는 별도로 집계하고 종료 코드 1을 반환한다.
기존 태그를 합집합으로 보존하고 `백년가게`를 추가한다. 수동 등 별도 출처의
L1/L2는 유지하고, 미분류 또는 Gemini 분류만 CSV 주요사업에 따른 분류로 보강한다.

`century_store_info`는 원본 파일명·SHA-256·연번·사업명·주요사업·주소·연락처·
매칭 근거·매칭 시각을 기록한다. **2022-07-13 자료에 수록된 이력**이며, 현재도
인증이 유지된다고 검증한 결과가 아니다. `current_certification_verified=false`와
`source_date`를 함께 저장한다. 재실행으로 기존 백년가게 플래그를 일괄 해제하지 않는다.

## Gemini와 저장 경로

기존 Gemini 리뷰 JSON에 `category_l1`, nullable `category_l2`, 다중 `filter_tags`를
추가한다. 유형별 enum과 태그 whitelist를 스키마에 넣고, Python에서 다시 검증한다.
주요사업과 TourAPI `firstmenu`/`treatmenu`를 사실 자료로 제공한다. AI에
`백년가게` 태그를 허용하지 않는다. 교정 후 장단점을 보존하는 경로에서도 분류 검증을
다시 수행하므로 잘못된 분류가 요약 복구를 통해 저장되지 않는다.

기존 모델 응답/테스트와의 호환을 위해 분류 필드가 전혀 없는 레거시 요약은 계속
처리한다. 신규 구조화 출력은 세 필드를 요구하며, 일부 필드만 있거나 잘못된 값은
검증 실패다. 근거 부족으로 생성되는 기존 `basic_info` 대체 요약은 AI 분류로
표시하지 않는다.

## SQL 준비 및 적용 순서

배치 DB(`SUPABASE_URL`의 프로젝트)에서 다음 순서로 적용한다.

1. `sql/place_taxonomy_setup.sql`: 요청한 6개 컬럼·GIN/복합/부분 인덱스와
   서비스 역할 전용 `apply_ai_place_taxonomy` 함수 생성.
2. 기존 리뷰 갱신 스키마가 있는 환경에서 `sql/ai_review_refresh.sql` 적용.
   큐 완료 함수가 요약과 장소 분류를 같은 트랜잭션으로 저장하게 한다.
3. Python worker 변경 배포 후 소규모 실행 및 실제 DB 값 확인.

SQL 함수는 SECURITY INVOKER와 빈 search_path를 사용하고 PUBLIC/anon/
authenticated 실행 권한을 제거한다. 장소 수정일과 활성 상태, L1 타입 및 태그
구조를 검사한다. 기존 리뷰 완료 함수의 리비전·리스 잠금 안에서 호출하므로 오래된
워커가 새 분류를 덮어쓰지 않는다. 수동·CSV 출처는 Gemini보다 우선하며,
현재 백년가게 플래그가 켜져 있으면 AI 갱신에서도 해당 태그를 보존한다.
인덱스가 특정 응답시간(예: 0.001초)을 보장하지는 않으며 운영 실행 계획으로 검증한다.

현재 REST 조회에서 컬럼은 모두 존재했지만, 배치 프로젝트 관리 토큰은 HTTP 401을
반환한다. 다른 연결 프로젝트에 SQL을 적용하지 않는다. 따라서 운영 인덱스 확인 및
함수 배포는 관리 접근 복구 후 수행해야 한다. 로컬 SQL 실행 테스트는 인덱스·재적용·
수정일 검사·우선순위·권한을 확인하며, 이는 운영 SQL 적용 증거가 아니다.

## 보류 168건 완화 재심사

```sh
python scripts/import_century_stores.py --resolve-review
python scripts/import_century_stores.py --resolve-review --apply
```

원본 `matching.json`은 덮어쓰지 않는다. 원본 CSV 해시가 같은지 검사하고, 당시
review였던 행만 최신 활성 장소와 재대조한다. 법인·본점·직영점 표기를 제거한
핵심 상호를 사용한다. 동일 시군구+핵심 상호 일치, 동일 시군구+포함 관계+전화
뒷자리 4자리, 동일 시군구+연속 3글자 이상+도로명/지번 번호 일치, 또는 최상위
후보 유사도 0.80 이상+차선과 5점 이상 차이 중 하나로 승인한다. 단일 후보는
차선 후보가 없으므로 유사도 조건으로 규칙4를 평가한다.

**요청된 규칙4 자체에는 지역 일치 조건이 없다.** 해당 경로로 승인됐지만
지역이 일치하지 않은 건수는 `accepted_without_region_match`에 따로 집계하며,
DB `century_store_info.region_match=false`로 기록한다. 이 값은 휴리스틱 승인이지
주소가 같은 사업체임을 확인했다는 뜻이 아니다. 규칙1~3은 시군구 일치를 요구한다.
단순한 도로명 숫자(예: 780번길의 780), 층수는 건물번호로 쓰지 않고,
`873-1`과 `873`을 같은 번지로 취급하지 않는다.

동점 후보·하나의 장소에 여러 CSV·기존 다른 CSV와 연결된 장소는 보류한다.
음식점 이외의 유형이나 별도 수동 출처의 분류도 이번 음식점 재심사에서 변경하지
않는다. CSV 주요사업을 PM v2 분류로 변환하고 기존 태그와 백년가게 태그를 합친다.
소스는 `century_seed`, 지정 이력의 `match_rule`은 `relaxed_review_pass`다.

PATCH 전 현재 장소 및 분류 필드 전체를 비교하고, 성공 후 100건씩 다시 읽어
저장한 모든 필드를 대조한다. 보고서는 적용 전 값과 적용한 PATCH도 보관한다.
같은 CSV를 재실행하면 이미 반영된 건은 재부여하지 않는다. 보고서 기본 경로는
`artifacts/century-stores/relaxed_applied.json`이다.

`--apply` 실행이 끝나면 원래 unmatched 918건과 이번 미승인/미반영 건을
`docs/unmatched_century_stores.json`의 records 배열에 연번 기준으로 합친다.
기존 대기 항목을 보존하고, 저장·검증된 승인 건만 제거한다. 이 JSON과 보고서는
실행 산출물이며 기존 로컬 데이터 제외 규칙을 따른다.
